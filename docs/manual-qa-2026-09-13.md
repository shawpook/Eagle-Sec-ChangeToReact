- **验证**：实机悬停「自动导入」→「设置」子窗格紧贴父项右侧（截图确认）。

### F4（Q5/Q6）：shims 桥接 main 逐文件导入回程 + 去重守卫 store 化

- **根因**：main `item:import-files` 逐文件 `event.sender.send('file-uploaded', item)`，

### F5（Q7）：BoxList rAF 自纠错重试收敛网格布局

- **根因**：v4（@egjs/infinitegrid 4.13）布局管线依赖 ResizeObserver 异步测量；
  `renderItems()` 在「新 children 提交、测量回调未回」窗口被调用后管线停摆 → 全网格
  条目无 inline 定位（CSS `position:absolute; top:3px; left:16px` 默认值叠加），
  视觉上「只剩 1 个条目」。触发面：冷启动首屏、会话恢复、任意运行中视图切换。
- **改动**（`components/grid/BoxList.tsx`）：渲染 effect 中同步 `renderItems()` 后，
  rAF 循环检查首个 `.box` 是否已被 v4 写入 inline `absolute` 定位；未定位则重调
  `renderItems()`（上限 30 帧，定位成功即停）。每次渲染的 cleanup 取消未完成的 rAF。
- **验证**：重载后连续切换 全部(60)→batch2 文件夹(8)→batch1 文件夹(27)，CDP 检查
  `positioned === boxCount` 全部通过；冷启动恢复视图亦正常。

### F6（Q8）：shims 的 fs-extra 映射修复（真实模块优先 + 扩展 API 兜底）

- **根因**：shims `bareModules['fs-extra'] = nativeFs || fsModule` —— fs-extra 被映射为
  普通 fs。`moveSync`/`removeSync`/`copySync`/`copy` 等扩展 API 全部 undefined。
  消费面：text-editor 保存（Q8 现象）、`fontTagService`（字体删除/复制）、
  `imageOpsService`（.bk 备份/复制副本）、`PluginFamily`（插件安装 copySync）、
  `ProgressDialogs`（导出 copy）——在 Electron 渲染层全部带病。
- **改动**（`frontend/public/shims.js` require 表）：
  1. Electron 下 `nativeRequire('fs-extra')` 取真实模块（`src/node_modules/fs-extra` 可解析）；
  2. 浏览器回退：以 fs 为底、按需补 `removeSync/remove/copySync/copy/moveSync/ensureDir(Sync)`
     门面（moveSync 先 renameSync、EXDEV/EPERM 回退 copy+remove）。
- **验证**：CDP 实证 `require('fs-extra').moveSync === 'function'`；txt 详情编辑 →
  autoSave 500ms → 原文件落盘（QA-EDIT-SAVED-VIA-FIX 行持久化）；清理 3 个孤儿临时文件。

### F7（Q10）：gl:\* 频道 handler 签名修正 + 待删元素捕获时序前移

- **根因（双叠加）**：
  1. `boxGridEngine.ts` 的 `glRemoveitemsChannel.on((_e, items) => …)` 与
     `glResetChannel.on((_e, items, cursor) => …)` 保留了 Angular `$on` 的「事件对象首参」
     签名；eagleBus（`global/bus.ts`）`emit`/`on` 是单 payload 语义（无事件对象）→
     handler 收到 payload 在 `_e` 上、真正的 items 形参恒 `undefined`：
     `gl:removeItems` 永远空集（删除后条目残留）、`gl:reset` 会 `applyReset(undefined)`。
     全仓 8 处 emit 均为单参（`emit(itemElements)`/`emit(allData)`），仅这两个 handler 错位。
  2. 原版（bundle 46424 邻域）`getSelectedItemElements()` 依赖 Angular `$watch` 在
     下一次 digest 才重建 `selectedMappings` —— 「先替换选中为 next、再捕获待删元素」
     的顺序在原版时序下仍能拿到旧选区。React 侧 `onSelectedChanged` 同步重建，
     同序捕获只能拿到 next 一项 → 修正为标记删除后立即捕获（两处：
     `libraryDomain.machineryRemoveFolderContents`、`selectionViewDomain.machineryRemoveSelected`
     全部/未分类分支）。
- **改动**：boxGridEngine 两个 handler 改单 payload 签名（gl:removeItems 加数组形状防御）；
  两处删除流把 `machineryGetSelectedItemElements()` 前移至自动选中之前，emit 复用捕获值。
- **验证**：batch1 文件夹（27 项）全选 → Delete：网格 27→0 即时清空、回收站计数 56
  （21 原有 + 35 测试项）、无残留；随后 API restore 35 项全部恢复（itemCount 263）。

### F8（Q11）：补挂 searchFilter 到 store

- **根因**：`filterDomain.ts` 的 `machinerySearchFilter`（bundle 32182 逐字移植）定义后

- **改动**：`filterDomain.ts` 模块内 machinerySearchFilter 定义后
  `useMiscRawState.getState().searchFilter = machinerySearchFilter`（对齐原版控制器初始化赋值）。
- **验证**：重载后 CDP 实测 —— `searchFilter` 为 function；搜「qa2-01」精确命中 1 项；

### F9（Q12/Q13）：侧栏平铺项直调映射补全 + 随机模式 shuffle polyfill

### 教训与备注

1. **三处「异步链吞错」型 bug（Q3/Q5/Q11）** 的共性：原版 scope 面函数/全局/polyfill 在
   React 移植中缺失，TypeError 被 promise/异步回调吞掉，用户侧表现为「静默无效果」。
   建议后续给 `runInBodyScope`、rebindRefresh、portal 回调的 console.error 接入统一开发期告警。

   `__eagleDataMachinery` 字符串路由表 vs scope 面直调的混用。建议后续全仓审计
   `Channel.on((_e` 形态与 `s[...]` 动态派发（本批已修 boxGridEngine 两处 + Sidebar 一处）。
3. 测试遗留物：默认库 `D:\饼.library` 中现有 40 个 `qa*` 测试条目与 3 个测试文件夹
   （manual-qa-assets / -batch2 / -batch3，均含 `qa` 前缀素材）；回收站中 21 个原有项未触碰。
