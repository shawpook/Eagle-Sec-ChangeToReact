### ❌ 絕對禁止事項
- **絕不** 在根目錄創建新文件 → Python 代碼使用 plugin/python/app/，主插件代碼使用 plugin/js/，演示插件使用 demo-plugin/js/
- **絕不** 直接將輸出文件寫入根目錄 → 使用指定的輸出文件夾
- **絕不** 創建文檔文件 (.md)，除非用戶明確要求
- **絕不** 使用帶有 -i 標誌的 git 命令（不支援互動模式）
- **絕不** 使用 `find`、`grep`、`cat`、`head`、`tail`、`ls` 命令 → 改用 Read、LS、Grep、Glob 工具
- **絕不** 創建重複文件（manager_v2.py、enhanced_xyz.py、utils_new.js）→ 始終擴展現有文件
- **絕不** 創建同一概念的多個實現 → 單一事實來源
- **絕不** 複製貼上代碼塊 → 提取到共享實用程序/函數中
- **絕不** 硬編碼應該可配置的值 → 使用配置文件/環境變量
- **絕不** 使用像 enhanced_、improved_、new_、v2_ 這樣的命名 → 擴展原始文件
- **絕不** 直接訪問 python-env/ 內的文件 → 使用 plugin/python/python.bat 或 python.sh 腳本

### 📝 強制要求
- **GITHUB 備份** - 每次提交後推送到 GitHub 以維護備份：`git push origin main`
- **使用 TASK 代理** 處理長時間運行的操作（>30秒）- 上下文切換時 Bash 命令會停止
- **TODOWRITE** 用於複雜任務（3個以上步驟）→ 並行代理 → git 檢查點 → 測試驗證
- **先讀取文件** 再編輯 - 如果你沒有先讀取文件，Edit/Write 工具將失敗
- **債務預防** - 在創建新文件之前，檢查是否存在類似的功能可以擴展
- **單一事實來源** - 每個功能/概念只有一個權威實現
- **Figma MCP** 一律要使用 get_code + get_image 兩個方式來確認圖像及實際代碼細節

### ⚡ 執行模式
- **並行任務代理** - 同時啟動多個 Task 代理以獲得最大效率
- **系統化工作流程** - TodoWrite → 並行代理 → Git 檢查點 → GitHub 備份 → 測試驗證
- **GITHUB 備份工作流程** - 每次提交後：`git push origin main` 以維護 GitHub 備份
- **背景處理** - 只有 Task 代理可以運行真正的背景操作
