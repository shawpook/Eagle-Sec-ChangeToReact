## 一、核心

1. **目标**：修 m1 中「folder drop import inserted duplicate item IDs」——同一 item 被 `file-uploaded` 事件**双发**（两个 id 各 ×2、两批间隔 252ms），itemDomain 监听把同一 item 两次 unshift 进 `s.raw`。
2. **本轮已证实的双总线结构（最关键事实）**：

   - itemDomain.ts:242 `const ipc = ipcRenderer()`（eagleGlobals.ts:41）在 Electron 下返回 `desktop.ipc`（真 IPC / preload contextBridge 桥）。

## 三、代码现状（怎么工作）

- **启动链**：vite（`frontend/vite.preview.config.mjs`）服务 `src/app/index.html`：head 注入 mock-data.js + shims.js，`</body>` 前注入 main.tsx。无 Angular（`window.angular` 缺席 → `global/scopeBridge.getBodyScope()` 建 shim scope 回填 `window.$bodyScope` → `attachCoreFnsToShim`（155 fns）→ `applyDataMachineryScope()` → 五域 takeover）。
- **drop 导入数据流（m1 断言面）**：
  m1（main.cjs 内嵌脚本）→ 构造 dataTransfer 调 `onDropContainer`（dataMachinery 端口）→ 走 scope 导入路径 → `ipc.send('upload-local-files'/'import-folders')` → **shims.js send 拦截段（~1600-1665）**：有 `desktopApi.import` 时 `desktopApi.import.files/folders(params)`（真 invoke → main.cjs `item:import-*` handle → backend job 轮询）→ `.then` → `emitImportedItems(items, channel)`（shims:960）→ mock `ipcRenderer.emit('file-uploaded', item)`（shims:983，经 911 行 emit 拦截器——其 angular 去重分支在 React 世界恒 fall-through）→ **itemDomain.ts:429 `ipc.on('file-uploaded')` 监听体**（bundle 30427 逐字：lastestAddItem、itemMappings、isDuplicateImage/duplicateQueue 判定、unshift 进 raw）→ m1 轮询 `scope.raw.find(name==='Dropped Text')` 通过。
  **双发即此链上同一 items 被两次送达监听体**（来源见一.4 三假说）。
- **双总线（关键）**：shims mock EventEmitter（shims:905）与真 IPC（preload `desktopApi`，`eagleGlobals.ts:41 ipcRenderer()` 优先取 `desktop.ipc`）是两条独立总线。`mockEmit('file-uploaded-end'/'import:operation-result'/'thumbnail-generated')` 等全部走 mock 总线；main.cjs `event.sender.send` 走真 IPC。**改任何一边前先确证监听挂哪条总线**（b25 教训）。
- **状态**：coreState（`core/appCore.ts`）唯一后端；`machinerySeedControllerState` 补种 controller-init 默认值（仅 `s.__eagleShim` 调用）。
- **双引擎**：`controllerFns.ts`（155 fns，@ts-nocheck）与 dataMachinery 有 ESM 循环 import（运行时安全——**勿"修复"**）。
